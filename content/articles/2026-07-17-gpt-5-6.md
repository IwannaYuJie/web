## 先说结论

7 月 9 日，OpenAI 正式发布 GPT-5.6 家族：旗舰档 **Sol**、均衡档 **Terra**，以及速度和价格优先的 **Luna**。

如果只看名字，这很像一次常规的模型换代；但把产品结构、工具调用和计费方式放在一起看，它更像一份新的 AI 工程报价单：

- 复杂研究、长时间编程和高难度决策，交给 Sol；
- 大部分日常生产任务，交给 Terra；
- 高频、标准化、对成本敏感的工作，交给 Luna；
- 真正棘手的任务，再用 `max` 或 `ultra` 增加推理与并行 Agent 预算。

换句话说，OpenAI 不再只卖一个“最强模型”，而是在卖一套可以按任务难度动态调度的智能资源池。

这比某个榜单又高了几分更重要。因为当 AI 真正进入公司流程，老板关心的通常不是“这个模型聪明不聪明”，而是：**同样一百美元，到底能稳定完成多少工作。**

## GPT-5.6 这次到底发了什么

三档模型都已经进入 ChatGPT、Codex 和 OpenAI API，但定位并不相同。

| 模型 | 官方定位 | API 输入价 / 百万 Token | API 输出价 / 百万 Token | 更适合什么 |
| --- | --- | ---: | ---: | --- |
| **GPT-5.6 Sol** | 旗舰、最高能力 | 5 美元 | 30 美元 | 长链路编程、复杂研究、高价值专业工作 |
| **GPT-5.6 Terra** | 均衡、日常主力 | 2.5 美元 | 15 美元 | 常规 Agent、代码维护、知识工作 |
| **GPT-5.6 Luna** | 最快、最便宜 | 1 美元 | 6 美元 | 分类、提取、批处理、高并发任务 |

这里最聪明的地方，是 **Sol、Terra、Luna 被设计成长期能力档位**。5.6 是这一代的编号，三个名字则可能按各自节奏继续升级。

这意味着开发者以后不必把产品逻辑绑死在某个完整模型版本上，而可以更像选择云服务器规格一样，选择“旗舰、均衡或经济型”。模型换代越来越像基础设施迭代，而不是每隔几个月重新装修一遍产品。

## 真正的关键词不是“更强”，而是“每 Token 更有用”

OpenAI 给 GPT-5.6 的核心叙事是 **performance per dollar**，也就是每一块钱能换回多少有效结果。

官方公布的评测里，Sol 在编程、浏览、电脑操作、科学和网络安全等方向都有提升。例如：

- Terminal-Bench 2.1 的普通 Sol 成绩为 88.8%，`ultra` 设置达到 91.9%；
- BrowseComp 上，Sol 为 90.4%，`ultra` 为 92.2%；
- OSWorld 2.0 上，Sol 为 62.6%，高于 GPT-5.5 的 47.5%；
- OpenAI 称 Terra 和 Luna 能以更低成本接近或超过上一代部分表现。

这些数字可以说明方向，但不能直接当采购结论。厂商评测会挑选自己关心的任务、工具环境和推理预算；你的客服工单、代码库、财务表格和内部知识库，分布往往完全不同。

更可靠的办法，是拿 30 到 100 个真实任务做一轮小型评测，同时记录四个指标：

1. 任务完成率；
2. 人工返工时间；
3. 总 Token 与工具调用成本；
4. 从提交任务到交付结果的总时长。

别只比较“一次回答多少钱”。一个便宜模型如果反复重试五次，最后可能比贵模型一次做对更贵。

## Programmatic Tool Calling：Agent 开始自己组织工具链

GPT-5.6 另一个值得盯住的变化，是 Responses API 里的 **Programmatic Tool Calling**。

传统 Agent 调工具时，常见流程是：模型决定调用工具，应用执行工具，再把完整结果塞回模型，模型继续判断下一步。数据量一大，中间结果会反复占用上下文和 Token，延迟也跟着上涨。

新的思路是让模型写一小段内存中的程序，用它来协调多个工具、过滤中间数据、监控进度，再把真正重要的结果留下来。它带来的价值不是“模型会写代码”这么简单，而是：

- 大量中间数据不必每轮都完整回灌；
- 工具之间可以先做确定性的筛选与转换；
- 长任务减少模型往返次数；
- 复杂 Agent 的成本和状态更容易控制。

比如做一次公司尽调，Agent 可能需要搜索网页、抽取几十份文档、清洗表格、比对工商信息。以前每一步都让模型重新阅读全部结果，很浪费；现在可以先用程序处理出异常项，再让模型集中判断。

这说明 Agent 架构正在从“LLM 一步一步遥控所有工具”，转向“LLM 临时编排一段小型工作流”。

## `ultra`：多 Agent 不再只是开发框架里的玩法

GPT-5.6 的 `ultra` 设置，默认会协调四个 Agent 并行工作。OpenAI 还展示了 16 Agent 的部分评测配置。

它适合可以拆分的复杂任务，例如：

- 多个 Agent 分头研究不同来源，再由主 Agent 合并结论；
- 一个检查安全、一个检查测试、一个检查性能、一个负责最终改动；
- 同时探索几种实现路线，再选择成功率最高的一条。

但多 Agent 不是免费的“聪明加倍”。它会增加 Token、工具调用、重复劳动和结果冲突。任务本身如果不可并行，硬拆成四份反而更慢。

一个实用判断是：**如果你能清楚写出各分支的输入、产物和合并规则，多 Agent 才可能划算。** 如果连人都不知道怎么分工，模型大概率也只会制造四份不同风格的混乱。

## 开发者应该怎么选

我会把三档模型当成一个路由问题，而不是站队问题。

### 默认先从 Terra 开始

Terra 更适合作为大多数产品的默认档。它的成本只有 Sol 的一半，官方定位又接近上一代旗舰。先拿它跑真实任务，失败或置信度不足时再升级 Sol，通常比所有请求一股脑上旗舰更健康。

### Luna 放在确定性较强的高频环节

分类、字段抽取、格式转换、简单摘要、批量内容审核，这些任务价值密度低但调用量大。Luna 的作用不是代替所有模型，而是守住成本底线。

### Sol 留给“做错一次就很贵”的任务

复杂代码变更、重要研究报告、跨系统排障和高价值专业工作，应该比较总返工成本。只要 Sol 能明显减少失败和人工复核，多出来的模型费通常很便宜。

### `max` 和 `ultra` 按任务开，不要全局常驻

更高推理预算适合少量困难任务，不适合默认开启。最好的产品体验不是让所有请求都跑最贵配置，而是建立难度识别、自动升级和成本上限。

## 这次发布暴露出的三个趋势

第一，**模型命名开始服务于调度，而不只是营销。** 当同一代模型被拆成稳定档位，应用层更容易建立长期路由策略。

第二，**Agent 的优化重点正在从 Prompt 转到执行结构。** 程序化工具调用、缓存、多 Agent、电脑操作，都是在解决“怎么把事情做完”，而不是“怎么回答得像”。

第三，**最高能力仍然重要，但经济型能力决定 AI 能铺多广。** 企业真正大规模部署时，绝大多数 Token 不会花在一次惊艳演示上，而会花在重复、琐碎、每天都要跑的流程里。

## 最后

GPT-5.6 最值得关注的，不是 Sol 又刷新了几个榜单，而是 OpenAI 把模型能力、推理预算、工具编排和多 Agent 并行放进了同一套产品结构里。

过去我们问：“哪个模型最强？”

接下来更有用的问题会是：

> 这个任务值多少钱？允许等多久？失败一次的代价多大？应该给它多少智能预算？

当这些问题能被系统自动回答，AI 才真正从一个聊天产品，变成可以计算、调度和治理的生产资源。GPT-5.6 只是把这条路画得更清楚了一点。🐱
